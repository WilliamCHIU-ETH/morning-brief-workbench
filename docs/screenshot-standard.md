# 截圖選頁標準（從真人剪輯反推）

## 意圖（2026-08-29，使用者與 agent 對齊後寫入）

**問題**：素材格「哪一句該配哪一頁、框什麼」目前是 `stages/capture-shots.mjs` 裡我們自己猜的
規則，不是來自任何被市場驗證過的標準。第一支端到端成片（`projects/20260826-yadian-test`）
已經出現三類選頁錯誤：同一頁連放兩格、旁白講成交量黃框卻在指數點位、一句點兩檔只開第一檔。
另外「哪些內容根本不適合配籌碼K線截圖」也還沒有判準——這個反面清單跟正面規則同等重要，
它就是 plan 階段「押回主播」的依據。

**做法**：從 IG `cmchipk` 真人剪輯的系列抽樣逐秒反推：每一句旁白配了什麼——主播還是截圖、
截圖是哪一頁、框了什麼、何時捲動或移框。要擴大樣本時回頭向使用者要授權。

**產出（都住在這份檔案）**：正面清單（句型 → 頁面 → 錨點）、反面清單（不配截圖的內容）、
對 `capture-shots.mjs` 的落地清單。

**成功判準**：規則回放到已拆解的 reel 逐素材格預測「配哪一頁」命中 ≥ 8/10；
下一支我們自己的片不再出現「同頁連放」「旁白與框不對題」。

**邊界**：本檔只管「句子 → 頁面 → 錨點」。節奏（素材何時出現）依使用者 2026-08-28 裁定維持
嚴格交替；對標影片的逐秒證據保留在本機、不隨 repo 發布，本檔只放蒸餾出的規則。

## 時間語意：晨報引用前一交易日收盤（2026-08-31 事故固化）

晨報在**開盤前**播出，旁白引用的是**前一交易日的正式收盤**（market_date=前一交易日、
state=official_close）。但 App 每一頁的 sticky 頁首永遠顯示「現在」——盤中是即時價、
盤後是今日收盤。0831 金居 v5 因此被判 BLOCKED：14s 加權、26s 國巨、33s 金居的頁首數字
與旁白衝突，金居漲跌方向甚至相反。

合法的取得管道只有兩條，**而且不對等**：

1. **首選：開盤前窗口（09:00 之前）截即時頁**——頁首本身就是前收，股名、價位、漲跌全部共存，
   構圖就是 0825 對標樣本的樣子（框頁首價位、一眼看得出是哪一檔）。
   正式產線（當天早上做當天晨報）一律走這條；這也是 2026-09-01 使用者 audit 指定的對齊目標。
2. **fallback：日K歷史選棒（`capture-shots.mjs --as-of YYYY-MM-DD`）**：
   「查價線」開啟後長按選中目標日 K 棒（放開後選取保留），accessibility tree 可直接讀到
   日期（`20xx/xx/xx`）與開高低收四個 StaticText，逐格驗證後截圖。
   注意「日／週／月」按鈕才是實際成交價；「還日▾」下拉是還原價，不要用。
   **三個代價**（2026-09-01 使用者 audit 逐一點名）：
   - **未來K棒不會回朔**：圖上仍看得到 as-of 之後的 K 棒（8/27、8/28…），觀眾看得出
     「這不是當天的畫面」。要解得做「平移圖表讓 as-of 棒成為最右一根」，目前未實作。
   - **幾何互斥**：`shot-template.mjs` 只有頂切 `cropTop`；個股頁股名列在 y114–174 px、
     即時價列在 y321–435 px，要把矛盾的即時頁首切掉（cropTop > 435）就必然失去股名列。
   - 構圖整體不如即時頁 header（對標樣本沒有這種日K特寫）。
   所以 --as-of 是「開盤前窗口錯過時的證據通道」，不是視覺上的等價替代。

**「回溯時間」的邊界（2026-09-01 查證該 App 原始碼後確認，不是猜測。原始碼屬公司內部資產，這裡只記結論）**：
- header 報價是依股票代碼訂閱的即時推播，請求不帶任何日期欄位，新舊靠傳輸序號分辨——**改裝置時鐘不會讓 header
  顯示過去收盤**，頂多讓連線壞掉。`simctl status_bar override` 只改狀態列貼皮，更不算。
- 該 App **沒有任何「指定觀察日期」機制**，也沒有會被編進正式版的除錯面板。
- 查價線的日期與 OHLC 讀的是本地已載入的 K 線陣列，選取當下不打 API。**它只是一般的圖表十字線功能，不是「時間回溯」**——
  任何看盤軟體都能在歷史K棒上讀到當日開高低收。--as-of 用它當「數字證據」可以，
  但不要把它說成 App 有回溯能力；App 沒有。

**回測（過去 docx 的測試片）的素材格政策（2026-09-01 使用者裁定）**：照 0825 構圖——
即時頁 header、不加 --as-of；header 數字必然是截圖日的，所以 **-test 目錄＋--test-mode 是
強制配套**（跟 0825 golden 自己一樣，shot-plan 記 mode: test），不得外流。這不是折衷，
是 App 端已證明沒有第三條路。

**禁止**：不得以字卡、遮蔽、後製標籤或修改模擬器時鐘把錯誤的即時畫面包裝成歷史資料

## 節奏：視覺窗口與拍點（2026-09-01 使用者 audit 固化；同日二修）

**第一性原理（一切節奏規則的生成器）**：觀眾聽到主張的每一刻，畫面上必須有
「在場、對位、可讀」的證據。在場＝窗口涵蓋主張的完整發聲區間；對位＝框住的**欄位**
就是旁白引用的欄位；可讀＝框到位之後有足夠的停留時間。任何新的節奏問題先問違反哪一面，
再決定進 gate、進規則、還是進交付自查。

四條配套規則（P1–P4，違反案例都來自 2026-09-01 使用者對 0827 的兩輪 audit）：

- **P1 欄位對應**：框選位置由旁白引用的欄位語意決定——「漲663點」框漲跌欄、
  「收在45,832點」框點位欄、「成交值」框成交量列、「收150.5元」框收盤欄——
  **不是**由數值匹配決定（test 模式下畫面數值本來就不同，欄位仍必須對）。
- **P2 主張錨定**：**一格的拍數由主張數決定**（同頁 N 拍用 focusList；排不下就明寫 skip 原因）。拍點的文字錨是**主張詞或主張子句的起點**（「663」「創下新高」「成交值」），
  永遠不是標的名（「強茂」）。錨錯在標的名會讓窗口錯位（00:37 事故：營收格在
  「創下新高」被說出前就關了）。
- **P3 拍點前導**：格進場沿用 lead 0.4s；**格內拍點切換同樣前導 0.4s**——主張子句開始說，
  框就開始移，到主張詞時已就位（對標的「畫面比聲音早半步」不只適用進場）。
- **P4 可讀停留**：每一拍從「框完全到位（tween 結束）」到「開始淡出」至少 **0.8s**；
  末拍同樣適用，6s 上限與段界 padding 對停留讓位（00:14 事故：成交量框 tween 完
  0.2s 就整格淡出）。

**交付前逐格三問（agent 自查，發生在給使用者看之前）**：**掃描單位是講稿主張，不是已排的拍點**——
從該格句子列出全部主張（數字、主張詞），逐一問：這個主張被說出的那刻證據在嗎（窗口）？
框的欄位對嗎（P1）？框到位後讀得清嗎（P4）？三問有一個答不出來就先修再交。
（2026-09-01 事故：三問若從 mg-plan 的 beats 出發抽定格，自己犧牲掉的主張永遠不會被自己抓到——
「收在45,832點」被靜默丟拍就是這樣漏掉的。同理，**主張要丟拍必須明寫 skip 原因**，
由 `shot.visual-window` 的主張涵蓋檢查 fail closed，不允許靜默犧牲。）

素材格的**邊界**是句子（嚴格交替不變），但素材圖層的**顯示窗口**不再等於句子——
主播是一條不斷的底，圖層窗口由以下規則計算：

- **R1 視覺窗口**：進場＝第一個拍點的字時間 − 0.4s（沿用 lead 夾限）；退場＝最後一個
  拍點講完 ＋ 約 1s，淡入淡出軟切。窗口下界 2s、目標上界 6s（對標帶 2–6s，
  對標影片的量測，資料保留在本機）；**「涵蓋全部拍點」優先於上界**。窗口一律 ⊆ 句子邊界。
- **R2 一句多主張＝多拍**：句內每個可指主張（數字、標的、可框錨點）是一個拍點，
  框（同頁）或頁（跨頁）在各主張的字時間切換。拍點是**文字錨**（同 emphasis 的 match），
  時間在 build 階段由 ASR 字時間解析——截圖階段沒有時間資料，只提供空間（focus／focus2／second）。
- **R3 卡片寧缺勿濫**：不加新資訊、或不改變觀眾對當下句子理解的卡，不上。
  卡片項**唸到才進場**（不是唸到才亮）；框在亮起時畫出、跨拍移動用 tween。

量測語意：coverage／alternation／material-floor 等內容結構 gate 維持句子語意
（它們管「多少內容由素材承擔」）；視覺窗口由 `shot.visual-window` gate 專管。
